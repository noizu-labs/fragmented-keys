# Fragmented Keys — Conformance

What every implementation in this composite must agree on to be considered
conforming (see [`ALGORITHM.md`](ALGORITHM.md) for the full algorithm):

- **Hash function** — MD5, applied to the composite string exactly as
  specified (key name, group id, then tags).
- **Separator characters** — `_` between key name and group id; `:` between
  every subsequent field. No other separators.
- **Field order** — key name, group id, then tags in the order supplied, each
  tag serialized as `t<name>` followed by `v<version>`. Order is significant.
- **Encoding** — the MD5 digest rendered as a hex string. Exact casing and
  numeric rendering of versions (int vs float) are **not yet pinned**.
- **Invalidation semantics** — bumping any constituent tag's version must
  yield a different composite key; invalidation must not delete entries.
- **Handler contract** — `get`/`set` plus a bulk multi-get, with tags grouped
  per backend so one round trip resolves a composite key.

## Cross-language compatibility status

Conformance to the rules above has **not** been demonstrated across the eight
vendored ports (`php`, `python`, `python-django`, `swift`, `java`, `go`,
`elixir`, `nodejs`). This section records the evidence that actually exists,
in exactly three categories:

- **Known compatible** — identical raw key string *and* digest demonstrated
  between two ports.
- **Known INCOMPATIBLE** — ports shown or documented in-repo to compute
  different keys from the spec (and from conforming ports) for the same
  logical input.
- **Untested** — **nobody has checked.** "Untested" is not a claim that a
  pair works; it means no evidence exists in either direction.

| Category | Ports / pairs | Basis |
| --- | --- | --- |
| Known compatible | `go` ↔ `python` | `go/testdata/golden_keys.json` was generated by running `fragmented-keys-py` (the Python reference implementation); the Go test suite replays it, comparing **both the raw key string and the MD5**. See `go/README.md`, "Why this port exists". |
| Known INCOMPATIBLE | `java` vs. spec-conforming ports; `swift` vs. spec-conforming ports | Both **sort tags instead of preserving insertion order**, so the same logical tag list serializes to a different string before hashing — a direct violation of this spec's field-order rule. **`swift` additionally skips hashing entirely**, storing raw composite strings as keys. Documented in `go/README.md`, "Compatibility with the other ports". |
| Untested | every other pair — `php`, `python-django`, `elixir`, `nodejs` against `go`/`python`/each other; `java` ↔ `swift`; and all remaining combinations | No cross-port vector set exists anywhere in this repository. `go/README.md` *asserts* key-compatibility with PHP, Elixir, and TypeScript (`nodejs`), but an assertion in a port's README is not evidence; those pairs remain untested here. |

### The failure is silent

When two ports disagree, **nothing errors**. Each side computes *a* valid
key, reads and writes its own entries, and works perfectly in isolation.
The only symptom is a **cache-hit-rate regression** that presents as a
performance problem, not a correctness bug — `go/README.md` calls it
"silent cache separation: both sides work, neither sees the other's
entries."

### Spec details not yet pinned

Two open points in [`ALGORITHM.md`](ALGORITHM.md) are each enough on their
own to split otherwise-identical implementations:

1. **MD5 hex digest casing.** The spec requires "the MD5 digest rendered as
   a hex string" but does not pin upper vs. lower case. `AB12…` and
   `ab12…` are the same digest and different cache keys.
2. **Version rendering.** The spec does not pin how version integers are
   rendered into the key string (`1` vs. `1.0`, float formatting, exponent
   forms). The spelling is hashed — the Go port ships a CPython-exact
   `repr(float)` reimplementation (`pyfloat`) precisely because of this.

### Cross-language vectors: a seed exists, not yet promoted

`go/testdata/golden_keys.json` — golden keys generated by running
`fragmented-keys-py`, verified as raw string *and* digest — is the right
**seed** for a real cross-language vector set. It currently lives only under
`go/` and has **not** been promoted to this directory. Until a shared vector
set lands here and every prefix is measured against it, no cross-language
conformance may be claimed beyond the `go` ↔ `python` pair above.
