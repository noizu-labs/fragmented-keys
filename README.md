# fragmented-keys-go

Go implementation of [fragmented keys](../docs/fractional-key-definition.md): composite cache keys built from independently versioned tags, where bumping one tag's version invalidates every key containing it — with no delete, no key scan, and no bookkeeping.

```
Key("Dashboard", [User:42, City:chicago])
  -> md5("Dashboard_:tUser_42GNP:v1748000000000.0:tCity_chicagoGNP:v5.0")
  =  371011c8520b2129c3231b1396adab4d

user.Increment(ctx)          # one write

  -> md5("Dashboard_:tUser_42GNP:v1748000000000.1:tCity_chicagoGNP:v5.0")
  =  b8d4e9f0…                # different key, guaranteed miss
```

The old entry is never deleted. It becomes unreachable and expires under its own TTL.

## Why this port exists

To let a Go service share a cache with the Django service in front of it. Not "compute similar keys" — the *same* keys, over the *same* stored bytes, in both directions.

That is verified, not asserted:

| Guarantee | How it is checked |
|---|---|
| Keys match the reference implementation | `fragkeys` replays [`testdata/golden_keys.json`](testdata/golden_keys.json), generated by **running fragmented-keys-py**, and compares the raw string *and* the MD5 |
| Version spelling matches CPython | `pyfloat` replays 2,389 CPython `repr(float)` values, including `+0.1` drift and the `1e16` notation switch |
| Stored bytes match django-redis | `djangoredis` decodes byte sequences captured verbatim out of Redis after Django wrote them |
| Both directions actually work | The pickle codec is tested against CPython fixtures; the handler against a live Redis (`FK_REDIS_ADDR`) |

## Use

```go
import (
    "github.com/noizu-labs/fragmented-keys-go/djangoredis"
    "github.com/noizu-labs/fragmented-keys-go/fragkeys"
    "github.com/redis/go-redis/v9"
)

rdb := redis.NewClient(&redis.Options{Addr: "…:6379", DB: 1})

// Point at the same Redis Django uses, with the prefix its
// configure_fragmented_keys(prefix=…) call sets.
h := djangoredis.New(rdb, djangoredis.WithCompression(true))
fragkeys.Config.SetDefaultCacheHandler(h)
fragkeys.Config.SetGlobalPrefix("GNP")

// Read a document Django may already have cached.
tag := fragkeys.NewStandardTag("Page", "careers")
doc, found, err := h.GetWithTags(ctx, "content_page", []fragkeys.Tag{tag})
if err != nil || !found {
    doc = compute()
    _ = h.SetWithTags(ctx, "content_page", doc, []fragkeys.Tag{tag}, 10*time.Minute)
}

// Invalidate for both runtimes at once.
_ = h.InvalidateTags(ctx, []fragkeys.Tag{tag})
```

With a key ring, when the same key shape recurs:

```go
ring := fragkeys.NewKeyRing(
    fragkeys.WithHandlers(map[string]fragkeys.CacheHandler{"redis": h}),
    fragkeys.WithDefaultHandler("redis"),
    fragkeys.WithGlobalTagOptions(map[string]fragkeys.TagOptions{
        "schema": {Type: fragkeys.TagConstant, Version: fragkeys.Float(0.1)},
    }),
)
ring.DefineKey("content_page", []fragkeys.Param{
    fragkeys.P("schema"), fragkeys.P("Page"),
}, fragkeys.TagOptions{})

key, _ := ring.KeyObj("content_page", "v0.1", "careers")
cacheKey, _ := key.String(ctx)
```

## Packages

| Package | Purpose |
|---|---|
| `fragkeys` | Tags, keys, key rings, configuration, in-memory handler |
| `djangoredis` | `CacheHandler` speaking django-redis's key naming and value encoding |
| `pypickle` | The JSON-shaped subset of Python pickle (protocols 0–5 in, 4 out) |
| `pyfloat` | CPython-exact `repr(float)`, because the version spelling is hashed |

`fragkeys` has no dependencies. `djangoredis` pulls in `go-redis/v9`.

## Interoperating with Django — read this before wiring it up

Three details decide whether the two runtimes actually meet. Getting any of them wrong produces silent cache separation: both sides work, neither sees the other's entries.

**1. The global prefix is appended, not prepended.** A tag name is `{tag}_{instance}{prefix}` — `("User","42")` with prefix `GNP` is `User_42GNP`. Match whatever `configure_fragmented_keys(prefix=…)` passes on the Django side. (Some `fragmented_keys_django` docstrings describe a `NOZ:tag:User:42` shape; the code does not produce that.)

**2. django-redis renames every key.** The physical Redis key is `{KEY_PREFIX}:{version}:{key}`, defaulting to `:1:…`. Note that Django reads `KEY_PREFIX` — a settings file specifying only `PREFIX` (which is the *fragmented-keys* suffix) leaves the Django prefix empty. `Handler.RedisKey` is exported so you can check this first when the two sides disagree.

**3. There may be two namespaces, not one.** `fragmented_keys_django`'s `FragmentedKeysCacheBackend` applies `make_key` and then hands the already-prefixed key to the wrapped backend, which prefixes it again. Which one a tag lands in depends on how it was built:

| Django-side construction | Physical key | Go setting |
|---|---|---|
| `backend.set_with_tags` / `get_with_tags` / `invalidate_tags` | `:1:<name>` | default |
| `model_tag()`, `ModelTagManager`, `@tagged_cache`, `invalidate_scope()`, bare `StandardTag()` | `:1::1:<name>` | `WithKeyFunc(DoublePrefixedKeyFunc("", 1))` |

Both can be live in one Django process, holding **different versions for the same logical tag**. Confirm which one the code you need to meet actually writes:

```bash
redis-cli -n 1 --scan --pattern '*<TagName>_*'
```

**4. Values are pickle, not JSON.** django-redis stores `zlib(pickle(value))`, except for non-bool ints which go in as raw decimal. `pypickle` covers the JSON-shaped subset; a Django value outside it (model instance, `datetime`, `Decimal`, `set`) returns an error wrapping `pypickle.ErrUnsupportedOpcode`. Treat that as a miss and recompute — do not fail the request.

## Compatibility with the other ports

Key-compatible with **PHP, Python, Elixir, and TypeScript**: MD5, `:t`/`:v` separators, `_` name separator, float versions with a `+0.1` increment, and insertion-ordered tags.

Not key-compatible with **Java or Swift**, which sort tags rather than preserving insertion order (and Swift skips hashing entirely). That divergence predates this port; see the comparison tables in the specification.

The dynamic key-ring accessor the dynamic languages offer (`ring.get_users_key_obj(...)`) is omitted — Go has no metaprogramming facility for it, and the specification marks it optional. Use `KeyObj("Users", …)`.

## Tests

```bash
go test ./...                                        # unit + golden vectors
FK_REDIS_ADDR=127.0.0.1:6380 go test ./djangoredis/  # + live Redis
```

The integration tests flush `FK_REDIS_DB` (default 15) on entry. Point them at a throwaway instance — `docker compose up -d redis` from the repository root gives you one on 6380.

Regenerating fixtures:

```bash
# Float corpus
python testdata/gen_pyfloat_repr.py > testdata/pyfloat_repr.txt

# Cross-port key vectors, from the reference implementation
cd ../fragmented-keys-py
.venv/bin/python ../fragmented-keys-go/testdata/gen_golden_keys.py \
    > ../fragmented-keys-go/testdata/golden_keys.json
```
